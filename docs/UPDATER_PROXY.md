# 软件更新代理

MCP DevDesk 的软件更新代理只影响 GitHub Releases 版本检查、SHA256 获取和更新包下载，不影响 MCP Core、Cloudflare Tunnel 或项目网络访问。

设置时只需要填写代理 IP/主机名和端口。程序会自动尝试 HTTP CONNECT 与无认证 SOCKS5，并缓存本次运行中识别成功的协议。常见本地端口如 7890、1080、10808 都可以通过“测试代理”确认。

“测试代理”会访问 GitHub，成功时显示识别出的协议和延迟；失败时分别显示 HTTP 与 SOCKS5 的错误。测试和检查更新都使用短连接超时，错误代理不会长时间锁住更新页面。

代理模式必须保持回退请求的响应体生命周期完整；当快速探测判断错误时，HTTP 与 SOCKS5 的实际请求仍会自动切换，并使用 Go 标准库的 SOCKS5 传输实现完成远程 DNS、连接复用和取消处理。

代理 IP 和端口填写完整后会短暂防抖并自动保存，成功时提示“已使用代理模式”。软件更新卡使用独立交互状态和原生按钮，避免某个代理请求影响整张卡片的其他操作；保存、测试、检查更新和立即更新会直接从 pointerdown 执行实际动作，并保留 click 作为键盘/普通浏览器兜底，避免 WebView2 只收到按下事件却吞掉后续 click。

代理回退响应体生命周期和标准 SOCKS5 传输均有自动化回归测试；正式发布前还必须通过 Windows CI 的前端构建、Go 测试和完整 Windows 构建。
