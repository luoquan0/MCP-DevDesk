# MCP DevDesk v0.12.39

## Fixed

- Fixed Cloudflare automatic configuration failing with `Tunnel 凭据文件不存在` after resetting portable data or reinstalling Windows and then logging in to Cloudflare again.
- When **优先复用同名 Tunnel** is enabled, MCP DevDesk still reuses the existing Tunnel when its credential JSON can be found or migrated from the legacy `.cloudflared` directory.
- If the same-name Tunnel exists remotely but its local `<UUID>.json` credential is truly missing, MCP DevDesk now treats that Tunnel as unrecoverable on this machine, deletes the stale remote Tunnel, recreates it with the same requested name, writes a fresh portable credential JSON under `data/devdesk/cloudflare`, and rebinds the hostname DNS to the new UUID.
- Added a short retry for Cloudflare's eventual-consistency window when the old Tunnel name has not been released immediately after deletion.
- Added regression tests for same-name replacement, portable credential generation, and name-conflict retry behavior.

## Why re-login alone was not enough

`cloudflared tunnel login` restores the account-level `cert.pem`, but it does not regenerate the per-Tunnel secret contained in `<UUID>.json`. Once that local secret is lost, the existing locally-managed Tunnel cannot be resumed from a fresh machine. v0.12.39 handles this state automatically when the user has explicitly selected same-name reuse.

## Scope

This patch does not change MCP authentication, portable AES secret storage, cloudflared binary update behavior, project validation, code navigation, terminal sessions, or the v0.12.37 installer preservation logic.
