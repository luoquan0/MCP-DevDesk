# 提示词模板与项目接班摘要

MCP DevDesk 的全局提示词和项目 `AGENTS.md` 支持从同一套模板库一键填入内容。模板只负责填入编辑框；只有用户继续点击保存后，目标提示词才会真正生效。

## 模板库

当前内置两套模板：

- **持续开发 · 自动接班**：适合长期连续开发。要求 Agent 尽量持续完成当前任务，并用短状态摘要帮助下一次会话快速恢复进度。
- **严格工程 · 发布闭环**：在持续开发规则基础上增加根因修复、最小改动、验证、敏感信息和发布纪律约束。

用户还可以在模板弹窗中创建、编辑和删除自己的模板。单个自定义模板最多 32 KiB，默认最多保存 20 个。

自定义模板存放在当前 DevDesk 界面所在浏览器 / WebView2 的本地存储中，不进入项目仓库，也不会自动跨不同浏览器来源或设备同步。套用到全局提示词后，实际保存位置仍是 DevDesk 数据目录；套用到项目规则并保存后，实际内容写入该项目根目录的 `AGENTS.md`。

## PROJECT_STATUS.md 约定

内置长期开发模板使用项目根目录的 `PROJECT_STATUS.md` 作为可覆盖的“当前开发状态缓存”。它不是第二份 `AGENTS.md`，也不拥有更高的指令优先级。

读取顺序建议为：

1. 先确认用户本轮明确要求。
2. 如果存在 `PROJECT_STATUS.md`，先读这份短摘要恢复进度。
3. 再读取当前目录适用的 `AGENTS.md` / 项目规则，并遵守更具体的约束。
4. 最后只读取当前任务真正相关的代码、文档、日志或 Git 历史。

发生冲突时，用户当前要求和适用的项目规则优先于 `PROJECT_STATUS.md`。状态文件只提供事实性进度，不用于覆盖项目规则。

## 上下文控制

`PROJECT_STATUS.md` 应采用覆盖式更新，而不是不断追加流水账。内置模板要求优先控制在 6 KiB 内，最多 8 KiB；超过时先压缩或删除旧信息再写入。

摘要只保留当前仍有用的信息：

- 当前目标
- 已完成结果
- 关键决策
- 真实阻塞
- 下一步
- 验证结果
- 关键文件和提交

不要把长代码、完整日志、聊天原文、已经失效的计划或重复历史复制进去。这样新会话可以先读几 KB 的状态摘要，再按需读取相关文件，而不是为了恢复上下文重新消费整个项目的 Markdown 和历史记录。

## 生效方式

- **全局提示词**：在“设置 → 软件设置 → 全局提示词”点击“使用模板”，选择模板后仍可编辑，最后点击“保存全局提示词”。全局规则由 DevDesk 注入 Go MCP，不写进项目目录。
- **项目规则**：在“项目与运行”中打开某个项目的 `AGENTS.md`，点击“使用模板”，选择模板后仍可编辑，最后点击“保存 AGENTS.md”。项目规则直接写入项目根目录。

模板机制不自动创建 `PROJECT_STATUS.md`。当用户套用了包含接班摘要规则的模板后，执行任务的 Agent 会在当前权限允许写文件且完成可独立交付阶段时创建或覆盖该文件。
